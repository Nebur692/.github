# Security Policy · Política de seguridad

🇬🇧 [English](#english) · 🇪🇸 [Español](#español)

---

## English

This policy applies to every public repository of [Nebur692](https://github.com/Nebur692) that does not have its own.

### Reporting a vulnerability

**Please do not open a public issue, pull request or forum post for a security problem.** Report it privately instead:

1. Go to the **Security** tab of the affected repository.
2. Click **Report a vulnerability**.
3. Describe the problem, the version affected and, if you can, the steps to reproduce it.

Only the maintainer sees the report.

### What to expect

- **A first answer within one week.**
- Once confirmed, the fix goes into a new release, and the report is credited unless you prefer to stay anonymous.
- If the report is not accepted, you will be told why.

### Supported versions

Only the **latest release** of each project receives security fixes. Please check that the problem still happens on it before reporting.

## Español

Esta política se aplica a todos los repositorios públicos de [Nebur692](https://github.com/Nebur692) que no tengan una propia.

### Cómo informar de una vulnerabilidad

**Por favor, no abras una incidencia pública, una pull request ni un mensaje en el foro para un problema de seguridad.** Infórmalo en privado:

1. Entra en la pestaña **Security** del repositorio afectado.
2. Pulsa **Report a vulnerability**.
3. Describe el problema, la versión afectada y, si puedes, los pasos para reproducirlo.

Solo el responsable del proyecto ve el aviso.

### Qué esperar

- **Una primera respuesta en una semana como mucho.**
- Una vez confirmado, el arreglo sale en una versión nueva, y el aviso se agradece con tu nombre salvo que prefieras quedar en el anonimato.
- Si el aviso no se acepta, se te explica por qué.

### Versiones con soporte

Solo la **última versión publicada** de cada proyecto recibe arreglos de seguridad. Comprueba que el problema sigue ocurriendo en ella antes de informar.
